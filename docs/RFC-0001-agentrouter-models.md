# RFC-0001: AgentRouter — каталог моделей

## Проблема

`getModels()` адаптера AgentRouter (`providers/agentrouter.js`) возвращает
`501 not_implemented`. На странице «Модели» каталог AgentRouter недоступен
— пользователь видит только модели xKiro (и Antigravity).

## Предпосылки

- AgentRouter — экземпляр платформы **new-api**.
- Авторизация двойная: System Access Token (Authorization Bearer) +
  числовой ID пользователя (заголовок `New-Api-User`).
- `GET /api/user/models` — стандартный эндпоинт new-api, возвращающий
  список id моделей, доступных аккаунту.
- Маршрут подтверждён на живом сайте: без токена отдаёт
  `401` с сообщением «未提供 access token» (тот же паттерн, что
  `/api/user/self`, который адаптер уже умеет авторизовать).
- Формат ответа — массив строк `["gpt-4o", ...]` или обёртка
  `{ data: [...] }`.

## Дизайн

Расширяем адаптер новой реализацией `getModels(key, userId)`:

1. Вызов `apiGet('/api/user/models', key, userId)` — те же заголовки и
   логика ретраев не-JSON с HTTP 200, что у `getUsage`.
2. Авторизационные ошибки обрабатываются тем же хелпером, что и
   `getUsage` (`401` или `200+success:false` → понятные подсказки).
3. Нормализация ответа:
   - если ответ — массив строк — берём как id;
   - если ответ — `{ data: [...] }` — извлекаем массив;
   - из каждого элемента извлекаем id (строка или поле `id`).
4. Возвращаем каталог в формате панели:
   `{ data: [{ id, access_tier: 'paid' }] }`.
   Цены и контекст new-api в этом эндпоинте не отдаёт — фронтенд
   «Модели» покажет прочерки.

## Безопасность

- Ключ и ID передаются серверу через заголовки (`x-api-key`,
  `x-agentrouter-user-id`) и не утекают в ответ клиенту (write-only
  секреты).
- `safeLog` отфильтровывает поля с именами token/key/secret/authorization —
  токены не попадают в логи.
- Адаптер не кеширует ответы; частота запросов низкая.

## Тестирование

Юнит-тесты в `test/agentrouter-adapter.test.js` (5 кейсов):

- 200 — массив строк → нормализован в каталог;
- 200 — обёртка `{ data: [...] }` + объекты с `id` → нормализуется;
- 401 без заголовков → `unauthorized` с подсказкой;
- не-JSON (HTML) → `bad_response` с диагнозом;
- неожиданная форма (нет списка) → `bad_response`.

Mock-сервер `startAgentRouterUpstream` (`test/helpers.js`) расширен
поддержкой ответов по конкретному URL (`opts.routes`) — обратно
совместимо.

## Ограничения и будущее

- `access_tier` всегда `'paid'`: new-api не сообщает тариф модели
  в этом эндпоинте. Если в будущем потребуется группировка по тарифу
  — можно читать `enable_groups` из `GET /api/pricing` (требует
  сопоставления, расширение за рамками этой итерации).
- «Окна расхода» для AgentRouter уже покрыты трекером
  (`day_balance_usd` на главной), дополнительных изменений
  не требуется.
