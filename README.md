# AI Панель

Дашборд для управления AI-разработкой: статистика потребления и остатков **xKiro** одной строкой, каталог моделей и combo OmniRoute — отдельными страницами с общей навигацией.

## Возможности

- **Навигация** — три страницы с общей шапкой: **Статистика** (главная), **Combo** и **Модели**
- **Провайдеры** — задаются в `.env` (`PROVIDERS=…`), у каждого свой адаптер-фабрика с функциями взаимодействия с его API (сейчас только xKiro)
- **Статистика провайдера** — выводится одной строкой с подписью «провайдер xKiro» (при появлении других провайдеров у каждого будет своя полоса)
- **Кошелёк** — баланс и сумма «в холде» (зарезервировано за запросы в полёте)
- **Окна расхода** — короткое (~5 ч) и длинное (~7 д) окна тарифа: потрачено / лимит / остаток / время до сброса с живым обратным отсчётом
- **Бесплатные токены** — дневная квота free-tier моделей
- **Каталог моделей** — отдельная страница (`models.html`): выбор провайдера, `/v1/models` с ценами ($/1M токенов), тиром доступа и поиском
- **Combo** — отдельная страница (`combo.html`): routing combo из вашего OmniRoute, состав targets по API и перестановка выбранной модели на первое место
- **Автообновление** — 10 с / 30 с / 1 мин / 5 мин / выкл; пауза, когда вкладка скрыта
- **Тёмная и светлая темы** — следуют системной настройке

## Запуск

### Вариант А — через локальный сервер (рекомендуется)

Нужен Node.js ≥ 18.

```
node server.js
# или
npm start
```

Откройте http://localhost:8765 — сервер отдаёт статику и проксирует запросы к API (обход CORS).

Порт можно поменять: `PORT=9000 node server.js`.

### Вариант Б — просто открыть файл

Откройте `public/index.html` в браузере. Если xKiro разрешит прямые запросы из браузера (CORS), всё заработает без сервера; иначе используйте вариант А.

## Настройка (.env)

Скопируйте `.env.example` в `.env` и заполните:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `8765` | Порт локального сервера |
| `PROVIDERS` | `xkiro` | Провайдеры через запятую; первый — активный (его статистику показывает панель). Пока поддерживается только `xkiro` |
| `XKIRO_NAME` | `xKiro` | Отображаемое имя провайдера |
| `XKIRO_API_URL` | `https://api.xkiro.com` | Адрес API xKiro (свой прокси / staging) |
| `XKIRO_API_KEY` | — | API-ключ xKiro (`sk-xt-…`). Если задан — панель работает сразу, вводить ключ в браузере не нужно |
| `OMNIROUTE_URL` | — | Адрес OmniRoute-инстанса (например `http://localhost:20128`). Если задан — панель проксирует запросы к `/api/combos` через `/omniroute/…` |
| `OMNIROUTE_API_KEY` | — | Management-ключ OmniRoute (создаётся в панели OmniRoute). Сервер сам добавит его в `Authorization: Bearer …` для запросов `/omniroute/…` |

Реальные переменные окружения (`PORT=9000 node server.js`) имеют приоритет над `.env`.

Если ключ в `.env` не указан — нажмите **⚙ Настройки** в панели, вставьте ключ, «Проверить и сохранить». Он сохранится в `localStorage` браузера и никуда, кроме api.xkiro.com, не отправляется

## Провайдеры

Список провайдеров задаётся в `.env`: `PROVIDERS=xkiro` (id через запятую, первый — активный). Для каждого — блок переменных `<ID>_NAME`, `<ID>_API_URL`, `<ID>_API_KEY`.

Логика работы с API конкретного провайдера — фабрика адаптера в каталоге `providers/`:

- `providers/xkiro.js` — `createXKiroProvider(config)` возвращает адаптер с функциями `getUsage(key)`, `getModels(key)` и авторизацией `x-api-key`
- `providers/index.js` — реестр: `FACTORIES` (id → фабрика) и `loadProviders(env)`, собирающий адаптеры из `.env`

Панель получает данные через эндпоинты сервера:

| Эндпоинт | Назначение |
|---|---|
| `GET /api/config` | Список провайдеров (`id`, `name`, `hasKey`) и активный — без секретов |
| `GET /api/providers/{id}/usage` | Статистика через адаптер провайдера |
| `GET /api/providers/{id}/models` | Каталог моделей через адаптер провайдера |
| `/proxy/{id}/v1/…` | Сырой прокси к API провайдера (или `/proxy/v1/…` — активный) |

Ключ: если клиент прислал `x-api-key` — используется он, иначе ключ из `.env`. Ответ upstream проксируется как есть (формат данных xKiro).

**Добавить нового провайдера:** файл `providers/<id>.js` с фабрикой по образцу `xkiro.js` (функции `getUsage`/`getModels`, `authScheme`, `upstream`), строка в `FACTORIES` в `providers/index.js`, переменные в `.env` (`PROVIDERS`, `<ID>_*`).

## Используемые API

| Эндпоинт | Назначение | Стоимость вызова |
|---|---|---|
| `GET https://api.xkiro.com/v1/usage` | План, окна расхода, бесплатные токены, кошелёк | Бесплатно |
| `GET https://api.xkiro.com/v1/models` | Каталог моделей с ценами | Бесплатно |
| `GET {OMNIROUTE_URL}/api/combos` | Список всех combo OmniRoute | — |
| `GET {OMNIROUTE_URL}/api/combos/{id}` | Детали combo (targets, strategy) | — |
| `PUT {OMNIROUTE_URL}/api/combos/{id}` | Обновить combo (перестановка targets) | — |

Деньги приходят строками (`"683.950000"`), парсятся во float только для отображения.

## Тесты

```
npm test        # или: node --test
```

Зависимостей нет — используется встроенный раннер Node (`node:test`):

- `test/providers-registry.test.js` — реестр провайдеров: чтение `PROVIDERS`, переменных `<ID>_*`, дубликаты, неизвестные id
- `test/xkiro-adapter.test.js` — фабрика адаптера xKiro против mock-upstream: пути, приоритет ключей, ошибки сети и формата ответа
- `test/server.test.js` — интеграционные: поднимается настоящий `server.js`, проверяются `/api/config`, `/api/providers/…`, оба формата прокси и статика

Реальный API xKiro не вызывается: тесты поднимают mock-upstream и переопределяют переменные окружения, так что локальный `.env` на результат не влияет.

## Combo (OmniRoute)

Страница **Combo** (`/combo.html`) управляет routing combo из вашего OmniRoute-инстанса. Ключ xKiro для неё не нужен — запросы идут через OmniRoute.

**Настройка:** укажите `OMNIROUTE_URL=http://localhost:20128` в `.env` (или переменной окружения). Панель будет проксировать запросы через `/omniroute/…`. Если инстанс требует management-авторизацию — создайте в панели OmniRoute ключ с правами management и впишите его в `OMNIROUTE_API_KEY` того же `.env`; сервер сам добавит его в заголовок `Authorization: Bearer …`. Ключ не попадает в браузер и не хранится в коде.

**Возможности:**

1. Выбор combo из списка — панель загружает все combo через `GET /api/combos`, при выборе — детали через `GET /api/combos/{id}`.
2. Просмотр списка targets (provider/model) с нумерацией и стратегией роутинга.
3. **Переставить первой** — выберите target в списке и нажмите кнопку; порядок обновится через `PUT /api/combos/{id}`.

Combo создаются и удаляются в самом OmniRoute (Dashboard → Combos). Панель только отображает и переставляет targets.

## Файлы

```
ai-panel/
├── server.js          # Node-сервер: статика + провайдеры + прокси + .env-загрузчик
├── providers/         # провайдеры AI-API
│   ├── index.js       # реестр: FACTORIES + loadProviders(env)
│   └── xkiro.js       # фабрика адаптера xKiro (getUsage, getModels)
├── test/              # тесты (node:test, без зависимостей)
│   ├── helpers.js     # mock-upstream и запуск server.js в тестах
│   ├── providers-registry.test.js
│   ├── xkiro-adapter.test.js
│   └── server.test.js
├── package.json       # скрипты start/test — зависимостей нет
├── .env               # настройки (порт, ключи провайдеров) — не коммитится
├── .env.example       # шаблон настроек
├── .gitignore
└── public/
    ├── index.html     # страница «Статистика» (главная)
    ├── models.html    # страница «Модели»: каталог моделей
    ├── combo.html     # страница «Combo»: routing combo OmniRoute
    ├── styles.css     # темы, навигация, полоса статистики, прогресс-бары
    └── app.js         # логика всех страниц: загрузка, рендер, отсчёт сбросов, автообновление
```
